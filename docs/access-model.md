# نموذج الوصول في PowerHub

يعتمد PowerHub على طبقات منفصلة للهوية والملف الشخصي والعضوية والنطاق. تستخدم الهوية **Manus OAuth**؛ لذلك لا يخزن PowerHub كلمات مرور محلية ولا يعرض رموز دعوات. يحمل كل حساب منصة القيمة `admin` في الدور التقني، ثم تحدد `platformRole` صلاحياته الفعلية على مستوى المنصة.

| التسمية التجارية | التمثيل التشغيلي | نطاق الوصول | الغرض |
|---|---|---|---|
| مالك المنصة | `admin` + `platform_owner` | المنصة كاملة | دعوة مشرفي المنصة، إدارة أدوارهم وحالات حساباتهم، والإعدادات الحساسة |
| مشرف المنصة | `admin` + `platform_admin` | المنصة كاملة | تشغيل المولدات والمستأجرين والدعم والمراجعة دون ترقية حسابات المنصة |
| مشرف مالي | `admin` + `finance_admin` | المالية المركزية | ملخص الاشتراكات والتحصيل المالي فقط، دون وصول للتشغيل أو الصلاحيات |
| صاحب مولد | `owner` | مساحة المستأجر | إدارة المحطات والمولدات وموظفيه وتشغيله المالي |
| مدير | `manager` | محطة معيّنة | متابعة التشغيل اليومي ضمن المحطة فقط |
| محاسب | `accountant` | محطة معيّنة | الفوترة والتعرفة والتقارير والتحصيل ضمن الصلاحيات الممنوحة |
| محصل | `collector` | محطة معيّنة | تسجيل التحصيل وجلسات المحصل دون صلاحيات فنية |
| فني | `technician` | محطة معيّنة | القراءات والتشغيل الفني دون تحصيل مالي |
| مشاهد | `viewer` | محطة معيّنة | عرض البيانات والتقارير المصرح بها فقط |

يقبل النظام دعوة منصة أو دعوة مستأجر فقط عند أول جلسة OAuth تحمل البريد المدعو نفسه وقبل انتهاء الدعوة. تنشئ دعوة المستأجر عضوية نشطة وتعييناً بالمحطة عند الاقتضاء؛ أما العضويات فتنتقل بين `invited` و`active` و`suspended` و`revoked`. الحسابات تحمل حالات `active` و`locked` و`disabled`، وتُرفض جميع الإجراءات المحمية للحساب المقفل أو المعطل. يُسجل تغيير دور المنصة أو حالته في سجل أمان مركزي، وتُسند سجلات تدقيق المستأجر إلى دور المنفذ على مستوى المنصة إن وُجد.

تُدار التفاصيل عبر `shared/powerhub-rbac.ts` وسياسات `platformRolePolicies`. هذه المواءمة تحفظ نموذج المحطة الدقيق الموجود بدلاً من اختزال تشغيل المولد إلى دورين فقط، مع جعل التسميات التجارية متسقة مع نموذج مدير المنصة وصاحب المولد والمحاسب.
