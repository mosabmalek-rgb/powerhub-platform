# حالة دمج TweetSMS الفعلي

## النطاق المعتمد

يدعم PowerHub حساب TweetSMS **مستقلاً لكل صاحب مولد**، مع اسم مرسل ومفتاح API يضيفهما مشرف المنصة فقط. تبقى حصة الرسائل وحدودها محصورة بكل صاحب مولد. لا تعرض واجهات المالكين أو سجل التدقيق مفاتيح الاعتماد، ولا يتغير وضع أي رسالة إلى **مسلّمة** ما لم يقدم المزود تقرير تسليم موثقاً.

| العنصر | الحالة الحالية | الضابط الأمني |
|---|---|---|
| عقد API-KEY ومسار الإرسال | موثق | تستقبل المنصة `999` للنجاح وتتعامل مع رموز الرفض المعروفة. |
| مفتاح API والرمز الإضافي | محفوظان مشفرين لكل صاحب مولد | لا يظهر المفتاح في الواجهة أو سجل التدقيق بعد الحفظ. |
| فحص اتصال الحساب | متاح لكل حساب مستقل | يستخدم فحصاً محدوداً للحساب والمرسل والرصيد ولا يرسل SMS. |
| الحصة | محسوبة بالشرائح | العربية حتى 70 حرفاً لرسالة واحدة، ثم 67 حرفاً لكل جزء متسلسل. |
| طابور الفواتير | جاهز محلياً | ينشأ داخل إصدار الفاتورة أو اختيارها اليدوي، ويُحجز ذرياً قبل اتصال المزود. |
| الإرسال الفعلي | غير مفعل في الإنتاج بعد | يتطلب نشر الدفعة وفحص الحساب المعني ثم موافقة صريحة على أول إرسال. |

## دورة التفعيل المقيدة

بعد نشر الدفعة على Vercel، يحفظ مشرف المنصة لكل صاحب مولد رابط TweetSMS الرسمي واسم المرسل واعتماد الحساب الخاص به في مركز الإدارة. يُشفر الاعتماد قبل تخزينه ولا يظهر ثانية في النموذج. ثم ينفذ فحصاً لا يرسل رسالة: يتحقق الفحص من الحساب واسم المرسل والرصيد إن كان الرمز الإضافي مطلوباً.

يظل الحساب غير نشط إذا تغيّر الرابط أو اسم المرسل أو المفتاح أو فشل الفحص. بعد النجاح، يفعّل مشرف المنصة الحساب صراحة. يقتصر أول اختبار إرسال لاحق على رقم اختبار يحدده المستخدم وبنص غير تشغيلي، ولا يستخدم أي مشترك حقيقي أو فاتورة أو مزامنة. وتبقى تذكيرات السداد وإيصالات التحصيل معلقة إلى حين نقل طوابيرها الذرية؛ لا تتأثر فواتير SMS بهذا القيد.

## ملاحظات التوافق

يعتمد عميل TweetSMS مسار API-KEY الموثق `https://tweetsms.ps/api.php/maan/` وصيغة نموذج مرمز. لا تستخدم المنصة حقول المجموعات أو الجدولة في هذا الإطلاق، ولا تستعمل أي مفاتيح أو رموز ظاهرة في أمثلة الوثائق العامة. [1] [2]
