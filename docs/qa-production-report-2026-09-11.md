# تقرير QA/E2E للإصدار المنشور

**المنصة:** PowerHub — `https://powerhub-platform.vercel.app/`  
**تاريخ التدقيق:** 11 سبتمبر 2026  
**نطاق التدقيق:** P7.3 وP7.4 والرحلات التشغيلية المرتبطة بالمصادقة، مساحة المالك، المولدات، المشتركين، القراءات، الفوترة، التحصيل، Offline/Sync، والعزل.  
**نوع الاختبار:** قراءة فقط حيثما أمكن، وبيانات اختبار معزولة وموسومة فقط عند الحاجة. لم تُرسل رسائل SMS أو WhatsApp، ولم تُنفذ دفعات أو تحصيلات أو مصروفات أو تغييرات Production.

## 1. الخلاصة التنفيذية

أُجري تدقيق عملي على النسخة المنشورة باستخدام حساب الأدمن ومساحة QA مؤقتة. نجحت حماية المسارات الأساسية، ونجح الدخول بحساب QA والوصول إلى مساحة فارغة مع مؤشرات صفرية، كما ظهرت صفحات المشتركين والمولدات والقراءات والفواتير والتحصيلات والميدان والمزامنة دون تسريب بيانات بين المساحات. نجح تنظيف بيانات QA بالكامل بعد انتهاء التدقيق، وبقي حساب الأدمن فعالاً.

لا أوصي باعتبار الإصدار **جاهزاً تشغيلياً كاملاً** قبل معالجة عطل إنشاء المشترك من واجهة المالك. كما توجد ملاحظة اتساق في واجهة إنشاء المولد: الخادم أنشأ المولد فعلياً، لكن صفحة المالك لم تحدّث القائمة أو تعرض رسالة نجاح مباشرة. بقيت المزامنة الفعلية وCRUD المالي الكتابي غير مثبتة لأن إنشاء المشترك فشل، وذلك مصنف **BLOCKED** وليس نجاحاً.

## 2. النتيجة الإجمالية

| المجال | النتيجة | الشدة | الدليل أو الملاحظة |
|---|---|---:|---|
| المصادقة وحراسة المسارات | PASS جزئي | P2 | الدخول بحساب QA نجح، والمسارات فتحت ضمن المساحة الصحيحة؛ `auth.me` غير المصادق أعاد جسماً فارغاً دون بيانات خاصة لكن بعقد HTTP غير واضح. |
| مساحة المالك والتوجيه | PASS | P2 | ظهرت مساحة QA والفرع الرئيسي والمؤشرات الصفرية دون بيانات خارجية. |
| إنشاء المولد | FAIL جزئي | P1 | واجهة `/generators` بقيت عند 0 دون Toast، لكن مركز الأدمن وSupabase أكدا إنشاء مولد QA واحد؛ المشكلة في اتساق تحديث الواجهة/النتيجة الظاهرة. |
| إنشاء المشترك | FAIL | P1 | محاولة إنشاء مشترك QA من `/subscribers` لم تنتج سجلاً أو رسالة نجاح قابلة للاستخدام؛ تم إيقاف إعادة المحاولة لتجنب التكرار. |
| القراءات | BLOCKED | P1 | صفحة القراءة تعمل وتعرض الحقول والطابور، لكن لا يمكن إثبات قراءة مرتبطة بمشترك دون نجاح إنشاء المشترك. |
| الفوترة | PASS قراءة فقط / BLOCKED كتابة | P1 | صفحة الفواتير تعرض الحماية والعدادات الصفرية، ولم يُصدر أي رقم فاتورة؛ الإصدار الفعلي غير مختبر. |
| التحصيل | PASS قراءة فقط / BLOCKED كتابة | P1 | الحساب المستقبِل إلزامي والفلاتر ظاهرة، ولم تُسجل أي دفعة أو جلسة تحصيل. |
| Offline UI | PASS جزئي | P2 | الطابور المحلي فارغ، وظهر إشعار الاتصال عند محاكاة offline محلياً؛ لم تُنشأ مسودة فعلية. |
| Sync الفعلية والتعارضات | BLOCKED | P1 | لم تُنشأ قراءة أو مسودة QA، لذلك لم يُختبر الإرسال، منع التكرار، التعارض أو إعادة المحاولة فعلياً. |
| العزل | PASS ضمن نطاق التدقيق | P1 | مساحة QA عرضت بياناتها الصفرية فقط، ومركز الأدمن أظهرها قبل التنظيف دون بيانات تشغيلية من مساحة أخرى. |
| الصلاحيات | PASS جزئي | P1 | الأدمن ظهر بمركز المنصة؛ حساب QA ظهر كمالك لمساحته. لم تُنشأ حسابات أدوار فرعية أو تُختبر مصفوفة الأدوار كاملة في هذه الجلسة. |
| المالية الحساسة | BLOCKED | P1 | لم تُختبر عمليات الدفع أو المصروفات أو التسويات كتابةً عمداً لتجنب آثار مالية، رغم عدم وجود بيانات عملاء حقيقية. |
| الاستجابة وUX | PASS جزئي | P2 | الصفحات الأساسية استجابت على سطح المكتب؛ توجد ملاحظات اتساق في رسائل النجاح، ولم يُنفذ اختبار جهاز جوال حقيقي في هذه الجولة. |

## 3. الرحلات المنفذة

### AUTH-01 وAUTH-02 — الدخول والتوجيه

تم إنشاء حساب QA مؤقت من مركز الأدمن، ثم نجح الدخول وتغيير كلمة المرور والوصول إلى صفحات المساحة. ظهرت ملاحظة مؤقتة حول استمرار رسالة تغيير كلمة المرور، ثم اختفت عند إعادة فتح الملف الشخصي؛ لذلك صُنفت كملاحظة اتساق P2 وليست فشلاً مؤكداً.

### SUB-01 — إنشاء المشترك

أُدخلت بيانات اصطناعية فقط، لكن الحفظ لم ينتج مشتركاً ولم تظهر رسالة قابلة للاعتماد. لم تتم إعادة المحاولة ولم تُنشأ بيانات مكررة. هذه نتيجة **FAIL P1** لأنها تمنع القراءة والفوترة والمزامنة التابعة.

### GEN-01 — إنشاء المولد

أُدخل مولد QA ببيانات اصطناعية. لم تُحدّث صفحة المالك عداد السجل بعد الإرسال، بينما أظهر الأدمن لاحقاً المولد والمساحة، وأكد فحص Supabase وجود سجل واحد قبل التنظيف. هذه نتيجة **FAIL جزئي P1 UX-Consistency**: العملية الخلفية تبدو ناجحة، لكن الواجهة لا تعكس النتيجة فوراً.

### READ-01 وFIN-01 — القراءة والفوترة والتحصيل

فتحت صفحات القراءات والفواتير والتحصيلات بحالة فارغة سليمة، وأظهرت ضوابط الفرع والفلاتر والطابور المحلي وإلزام اختيار الحساب المستقبِل للتحصيل. لم تُنفذ أي كتابة مالية أو إصدار فاتورة أو إرسال إشعار.

### OFF-01 وSYNC-01 — Offline/Sync

ظهر مؤشر الاتصال والطابور المحلي الفارغ، وتمت محاكاة حدثي offline وonline محلياً دون قطع الشبكة الفعلية. لم تُنشأ مسودة قراءة، ولم تُشغّل مزامنة أو تعارض فعلي؛ النتيجة **PASS للواجهة فقط وBLOCKED للمسار التشغيلي الكامل**.

## 4. الأمان والعزل

المسارات المحمية لم تعرض بيانات تشغيلية لزائر غير مصادق. مركز الأدمن أظهر مساحة QA ومالكها أثناء الاختبار، ثم اختفت بعد التنظيف. اختبار `auth.me` بدون Cookie لم يُرجع بيانات مستخدم، لكنه أعاد استجابة HTTP 200 بجسم فارغ؛ يوصى بتوحيد هذا العقد إلى استجابة صريحة ومفهومة.

## 5. التنظيف والتحقق

قبل التنظيف كانت مساحة QA تحتوي موقعاً واحداً ومولداً واحداً وعضواً واحداً وسجلّي تدقيق، ولا تحتوي مشتركين أو قراءات أو فواتير أو دفعات أو مصروفات أو أحداث مزامنة. حُذفت مساحة `tenant_id=16`، والمستخدم QA ذي المعرف 495، وAuth UUID المرتبط به ضمن معاملة محددة بالاسم والبريد والمعرفات.

تحقق Supabase بعد الحذف من: `qa_tenant_remaining=0`، و`qa_user_remaining=0`، و`qa_auth_remaining=0`. كما تحقق من بقاء حساب الأدمن `MrMosab1979` فعالاً بدور `admin/platform_owner`. وأعيد تحميل مركز الأدمن بصرياً، فلم تعد مساحة QA أو المولد أو المالك ظاهرة.

## 6. القرار والتوصيات

**قرار QA:** الإصدار صالح للمراجعة والاختبار المراقب، لكنه ليس جاهزاً لاعتماد تشغيلي كامل بسبب فشل إنشاء المشترك وكون مسار Offline/Sync الفعلي غير مثبت.

الأولوية الأولى هي فحص طلب إنشاء المشترك في Production logs وSupabase RPC وإضافة اختبار واجهة يمنع الفشل الصامت ويعرض رسالة خطأ قابلة للإجراء. بعد الإصلاح، ينبغي إعادة اختبار دورة مشترك → قراءة → اعتماد → فاتورة مؤجلة دون SMS، ثم اختبار طابور Offline/Sync والتعارض بمساحة QA جديدة. بعد نجاح ذلك فقط يُعاد تقييم الجاهزية، مع إبقاء SMS والمدفوعات الحقيقية خارج QA أو خلف موافقات منفصلة.
