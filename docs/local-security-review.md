# مراجعة PowerHub المحلية: العزل والصلاحيات

## سياسة النطاق

تعامل المنصة **مالك المستأجر** بوصفه مالكاً لكل المحطات التي تقع ضمن مساحة المستأجر نفسها. أما أدوار المحطة، وهي المالك المحلي والمدير والمحاسب والمحصل والفني والمشاهد، فتعتمد على سجل `staffProfiles` النشط للمحطة المحددة. لا تمنح عضوية المستأجر من نوع `member` وحدها أي وصول لمحطة لا يملك المستخدم تعييناً نشطاً عليها.

تتحكم الدالة `resolveRole` في هذا القرار، بينما تعيد `sites.list` للعضو محطات تعييناته النشطة فقط. لا يجعل تعيين مستخدم بوصفه مالكاً لمحطة واحدة عضواً مالكاً في مساحة المستأجر؛ تبقى عضويته `member` ما لم يكن مالك المستأجر مسبقاً.

## حدود اختبارات التكامل

يتحقق `server/tenant-isolation.integration.test.ts` من الحالات الآتية باستخدام مستأجرين ومحطتين في المستأجر الأول:

| الحالة | النتيجة المتوقعة |
|---|---|
| مالك مستأجر يصل إلى محطتيه | مسموح |
| مدير محطة يصل إلى محطته الأخرى غير المعيّن عليها | مرفوض |
| عضو مستأجر غير مكلّف بمحطة | لا تظهر له المحطة ولا يقرأ بياناتها |
| مالك محطة مكلّف عبر الفريق فقط | يعمل مالكاً لمحطته ولا يرى المحطة الأخرى |
| مستخدم مستأجر آخر يعيد محاولة إشعار | مرفوض |
| محصل أو فني أو مشاهد ينفذ إجراءً خارج قدرته | مرفوض |
| عملية قراءة ميدانية تعاد بنفس المعرّف | تعاد النتيجة من دون سجل قراءة مكرر |

## مصفوفة المراجعة النهائية للأدوار والمسارات

تربط هذه المصفوفة بين كل قدرة حساسة وآلية تحقق محلية. وهي مراجعة وظيفية محلية، ولا تعني أن حسابات Meta أو مزود SMS أو النشر الخارجي قد فُعّلت.

| الدور أو المسار | الواجهة أو الإجراء الحساس | آلية التحقق | النتيجة المحلية |
|---|---|---|---|
| مالك المستأجر | المحطات التابعة للمستأجر وإدارة الفريق | اختبار عزل المستأجرين | يرى محطاته فقط، ويستطيع إدارة فريق المحطة من دون ترقية مالك المحطة إلى مالك مستأجر |
| المالك | إعدادات قنوات المراسلة | اختبار حواجز الواجهة | يظهر نموذجا WhatsApp وSMS منفصلان للمالك فقط |
| المدير | الوصول إلى محطة غير مكلّف بها | اختبار عزل المستأجرين | مرفوض، ولا تظهر المحطة ضمن القائمة |
| المحاسب | إصدار الفاتورة ومراجعة البيانات المالية | اختبار حواجز الواجهة واختبار التكامل | تظهر أداة الإصدار للمحاسب، وتُنشأ الفاتورة وبنودها ضمن المستأجر والمحطة الصحيحتين |
| المحصل | جلسة التحصيل وتسجيل الدفعات | اختبار عزل المستأجرين وحواجز الواجهة | يستطيع التسجيل ضمن جلسة مفتوحة فقط، ولا يصل إلى سجل التدقيق |
| الفني | تركيب العداد وتسجيل القراءة | اختبار حواجز الواجهة واختبار العزل | تظهر أدوات العداد والقراءة، وتُرفض الدفعات المالية |
| المشاهد | الدليل والفوترة والعمليات | اختبار حواجز الواجهة | واجهة قراءة فقط؛ لا تظهر أدوات الإنشاء أو التحصيل أو القراءة |
| الفاتورة العامة | `/invoice/:token` من دون جلسة دخول | اختبار واجهة مستقل | يعرض رقم الفاتورة والمشترك والبنود وأدوات النسخ والطباعة عند وجود رابط صالح |
| لوحة الملخص والتقارير | اختيار المحطة وعرض مؤشرات التشغيل والمالية | اختبار واجهة مستقل | تعرض المحطة المحددة ومؤشرات لوحة التحكم والتقرير وتتيح CSV عند توفر البيانات |
| إشعار الفاتورة | قناة WhatsApp وSMS النشطة للمستأجر | اختبار وحدات واختبار عزل تكاملي | ينشئ الطابور رسالة لكل قناة نشطة، مع بديل WhatsApp محلي عند غياب التهيئة |

## حدود اختبارات الواجهة

يتحقق `client/src/pages/role-guards.ui.test.tsx` من حواجز الواجهة للأدوار الستة عبر الفوترة ودليل الشبكة وإعدادات المراسلة وإدارة الفريق والعمليات والقراءات. ويضيف `client/src/pages/supplemental-pages.ui.test.tsx` تحققاً مستقلاً لصفحة الفاتورة العامة ولوحة الملخص والتقارير واختيار المحطة. هذه الاختبارات لا تستبدل تفعيل أو اختبار المزود الخارجي؛ إذ يظل ذلك خارج النطاق المحلي المؤجل.

## أوامر التحقق المحلية

```bash
pnpm check
pnpm test
RUN_TENANT_ISOLATION_TESTS=1 pnpm vitest run server/tenant-isolation.integration.test.ts
pnpm build
```

تتحقق هذه الأوامر من الأنواع، واختبارات الواجهة، واختبارات الخادم العادية، وعزل قاعدة البيانات الفعلي، والبناء الإنتاجي. لا تغطي عمليات النشر أو إرسال مزود خارجي؛ إذ تظل هذه التفعيلات مؤجلة بطلب المستخدم.
