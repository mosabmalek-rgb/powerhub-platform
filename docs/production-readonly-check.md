# سجل تحقق الإنتاج للقراءة فقط

## 27 أغسطس 2026

تم فتح الصفحة العامة في `powerhub-platform.vercel.app` وتلقت استجابة واجهة صحيحة. كما أعاد مسار الصحة العام عبر tRPC النتيجة `ok: true` عند تمرير طابع زمني صحيح.

تم تسجيل الدخول بحساب مالك المنصة الذي وفره المستخدم، ثم فتح `/admin` بلا أي إنشاء أو تعديل بيانات أو إرسال رسائل. ظهرت واجهة مركز الإدارة وهوية **مشرف منصة** والقوائم المركزية، ما يثبت جلسة Supabase Auth ومسار الحماية للقراءة.

أظهر الفحص أن مؤشرات لوحة الإدارة الحالية بلا بيانات تشغيلية، وظهر عرض غير رقمي لنسبة التحصيل. سُجل بند تصحيح محلي منفصل لمعالجة حالة غياب بيانات التحليل. لا يعني هذا السجل اكتمال اختبار Mobile API أو اكتمال ضبط متغيرات Vercel السرية.

اكتمل لاحقاً تصحيح محلي لعرض نسبة التحصيل بحيث تعرض البطاقة قيمة صفرية عند غياب قيمة رقمية. أما التحقق المصادق عليه لـMobile API فلا يمكن إجراؤه من كلمة مرور الويب وحدها من دون إنشاء جلسة موبايل جديدة؛ يحتاج رمز وصول ميداني قائم ومصادق عليه، أو موافقة منفصلة على إنشاء جلسة اختبار موبايل قابلة للإبطال.

## النشر المعتمد — 27 أغسطس 2026

بعد موافقة المستخدم الصريحة، دُفعت النقطة المحلية إلى `github/main` عند الالتزام `23e39eb3721dc06ba2cb701fa99cf858b54d022f`. وصل النشر التلقائي المقابل في Vercel إلى الحالة `READY` للإنتاج.

أعيد اختبار الصفحة العامة، ومسار الصحة `system.health` بعقد tRPC صحيح وأعاد `ok: true`، ثم فُتح `/admin` من الجلسة المصادق عليها. حمل مركز إدارة المنصة ومؤشر نسبة التحصيل بقيمة `0%` من دون ظهور قيمة غير رقمية. لم تُنشأ أو تعدل بيانات ولم تُرسل رسائل خلال هذه الاختبارات.

أظهر فحص Vercel التجميعي لأخطاء وقت التشغيل خلال الساعة التي تلت النشر عدم وجود أخطاء تشغيل مسجلة. أُغلقت جلسة المتصفح بعد انتهاء اختبار القراءة فقط.

## اختبار Mobile API المؤقت

بموافقة صريحة من المستخدم، جرى طلب تسجيل الدخول إلى Mobile API بوسم جهاز اختبار. أعاد المسار `409 TENANT_SELECTION_REQUIRED` لأن حساب مشرف المنصة المتاح لا يملك عضوية في أي مستأجر. لم يرجع المسار رمز وصول أو رمز تجديد، ولذلك لم تُنشأ جلسة موبايل ولم يلزم إبطالها. يلزم حساب فني أو مالك منضم إلى مستأجر، ومفعل له `accessFieldApp` و`recordReadings`، لإتمام اختبار القراءة المصادق عليه.

أُنشئ لاحقاً نطاق ميداني مؤقت منفصل ومقيد بمستأجر وفرع واحد وصلاحيتي `accessFieldApp` و`recordReadings` حصراً. اقتصرت محاولة الاختبار على `POST /api/mobile/v1/auth/login` ولم تطلب أي قراءة تشغيلية أو مزامنة. توقفت المحاولة عند `503 DATABASE_UNAVAILABLE`، وأظهر سجل وقت التشغيل في Vercel الرسالة: `Mobile API authentication is not configured`. لم يصدر أي رمز وصول أو تجديد، ولم تُنشأ جلسة موبايل، ولذلك لم يكن هناك رمز لإبطاله.

بعد التوقف، حُذفت كل بيانات الاختبار بالترتيب العلاقي، بما يشمل النطاق والفرع والعضوية وملف الموظف والمستخدم وحساب المصادقة. أكد استعلام تحقق قرائي أن عدادات النطاق والفرع والعضوية وملف الموظف وجلسات Mobile API والمستخدم جميعها تساوي صفراً. يبقى الاختبار النهائي للهوية (`login` ثم `auth/me` ثم `logout`) مفتوحاً إلى أن تُتاح تهيئة مصادقة Mobile API في بيئة Vercel الإنتاجية؛ لا يعني نجاح الصفحة العامة أو مسار الصحة اكتمال هذا المسار.

بعد إضافة `JWT_SECRET` إلى بيئة Production في Vercel بإذن المستخدم وإعادة النشر إلى حالة `READY`، أُعيد إنشاء نطاق فني مؤقت مستقل بصلاحيتين حصراً: `accessFieldApp` و`recordReadings`. نجح `POST /api/mobile/v1/auth/login` بحالة `200`، ثم نجح `GET /api/mobile/v1/auth/me` بحالة `200` وأكد دور `technician` ونطاق فرع واحد. لم تُطلب قائمة مشتركين أو قراءات أو مزامنة أو أي بيانات تشغيلية.

أعاد `POST /api/mobile/v1/auth/logout` الحالة `204` لإبطال الجلسة. بعد ذلك حُذفت جلسة الاختبار وكل سجلات النطاق المؤقت وحساب المصادقة، وأكد تحقق قرائي مستقل أن عدادات المستأجر والفرع والمستخدم والعضوية وملف الموظف وجلسات Mobile API جميعها تساوي صفراً. وبذلك اكتمل اختبار عقد الهوية الإنتاجي ضمن الحد المصرح به، من دون كشف رموز أو كلمات مرور أو معرفات حساسة.
